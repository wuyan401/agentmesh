# 架构与不变量

这份文档解释 AgentMesh **为什么**长成这样。协议（怎么做）在 [PROTOCOL.md](../PROTOCOL.md)，
验收证据在 [ACCEPTANCE.md](ACCEPTANCE.md)。

---

## 1. 三层分离

| 层 | 内容 | 平台态度 |
|---|---|---|
| **能力层** | Agent 自带的一切原生工具：Bash、读写、搜索、子 Agent、Web、浏览器…… | **完全开放，零限制** |
| **环境层** | 进程的 cwd、TTL、会话标识、注入的 MCP server | 平台设定（世界长什么样） |
| **职责层** | 角色、scope、任务状态机、产出裁决权 | 平台强制（允许做什么事） |

约束点全部落在环境层与职责层。**能力层没有任何开关**——这是有意的：
- 威胁来源从来不是“用了 grep 还是内置搜索”，而是“写了不该写的路径”和“做了职责外的事”；
- 能力被阉割的 Agent 任务质量下降，用户会发现直接用 Agent 比走平台效果好 → 平台被抛弃；
- 工具全开后，P-Session 相对 D-Session 是纯增益，粘性来自超集优势而不是约束。

## 2. 脱轨的根因与解法

一个 Agent 同时满足三条时会必然自己包办：**知道全局目标 + 拥有直接执行能力 + 无交付门槛**。

- 第 2 条不可剥夺也不应剥夺（C4）——没收工具只会制造绕开平台的动机。
- 于是砍第 1 条（环境默认不见全局，**软防线**），改造第 3 条（产出必经裁决，**硬防线**）。

最终答案拆成三个保证：

| 保证 | 机制 |
|---|---|
| **结构保证** | Worker 是平台拉起的 ephemeral 进程：它的世界 = 一个沙箱 + 一张任务卡 + hub 工具 + 自己的全部原生工具。它**就在平台里**；submit 后进程即终止 |
| **经济保证** | 不 submit = 白做。绕过平台的一切工作在合并终审处归零 |
| **激励保证** | 超集性：走平台比绕开平台能力更多、上下文更省、步骤更少 |

长驻角色（协调、审查、集成、审计）无法靠“进程即终止”约束，所以它们的职责在**代码里**封死：
Coordinator 的 `put_artifact` 对代码路径直接拒绝；Integrator 只能通过 `hub.merge` 合并；
Sentinel 只有读 + 写审计两个动作。

## 3. 六个不变量，以及它们在哪儿被强制

### C5 · 确定性核心

`hub/core/stateMachine.ts` 是唯一能改 `task.status` 的代码。所有跃迁经 `applyTransition` 校验边、
写 history、拒绝非法跃迁。LLM 只能*请求*跃迁（`hub.submit` 等），不能宣布结果。

### C6 · 单角色会话

`IdentityService.createSession` 把 role 写进 SessionCard；每次特权调用都走
`requireIdentity(sessionId)` → 重新读卡 → 重新取 RoleCard。没有“切换角色”的 API，
因为角色不是运行期状态，是出生属性。

### C7 · 审查独立

两道：
1. 调度器 `pickAgent` 用 `sodConflict` 过滤掉实现者；
2. `Board.recordVerdict` 里 `assertIndependentReviewer` 再校验一次——即使有人手工伪造调用，
   也无法让同一个 Agent 给自己的任务写 verdict。

### C1 · 裁决权

`Board.mergeTask` 的第一步就是 `approvedReview(task)`：没有 approved 的审查记录，
连合并的入口都进不去。`MergeRefused` / `ScopeViolation` 会把整单打回并留证据。

### C4 · 职责约束而非能力约束

- `RoleCard` 结构里**没有** tools 字段；`validateRoleCard` 会拒绝带 `tools`/`tool_policy` 的卡。
- 适配器产出的启动配方（命令、args、patch、env）同样没有“限制工具”的表达力。
- `put_artifact` 只收非代码工件，按角色 `output_globs` 校验——它管的是**产出路径**，不是文件操作闸门。

### C2/C3 · 超集性与双模边界

- 超集性：P-Session = 原生工具（全）+ hub 工具（增）。适配器只做加法。
- 双模边界：MCP 注入通过**会话私有**的 `--patch` 覆盖文件实现（dsh）或一次性 config 文件（cli-generic），
  从不写共享 profile。平台没有任何代码路径能读到“用户直接打开的 CLI 会话”，更没有注入点。

## 4. 为什么沙箱是 clone 而不是 worktree

`git worktree` 把每个 worktree 的元数据放在 `<主仓库>/.git/worktrees/<name>`。
也就是说：**沙箱的 git 元数据在沙箱外面**。

任何自带工作区写沙箱的 CLI（DeepSeek Harness 的 file sandbox、Claude Code 的 `--sandbox`、
Codex 的沙箱模式）都只能写“工作区”内的路径——于是 `git add` 无法创建 `index.lock`，
`git commit` 直接失败。第一个真实 Worker 就卡在这里（见 ACCEPTANCE 里的「真实缺陷」一节）。

改成**自包含 clone**（`git clone --shared`）之后：
- `.git` 在沙箱内，最严格的写沙箱也能提交；
- 隔离更强：不共享索引锁，没有从沙箱通往主仓库对象库的写路径，`origin` 被移除（没有 push 暗道）；
- 代价：合并前需要 `git fetch <沙箱> +refs/heads/<branch>:refs/mesh/<task>` 把提交取回平台仓库。
  这一步是只读的，且让"平台仓库里有什么"始终由平台自己决定。

## 5. 消息总线：角色线程

寻址到**角色线程**而不是 Agent：

```
to: { role: "supervisor", thread: "T-0042" }
  → Hub 查当前在任者 → 投递到其收件箱 + 长轮询推送
  → 无人在任 → 进角色队列，等下一个接手该角色的人
```

好处：角色换人不丢上下文；投递自动解析；**Agent 永远无法点对点私聊**（C8）——
`send` 只接受 role，传 agent id 会直接 `MESH_BUS_BYPASS`。直连会形成平台外暗道，
让审计失效，并天然导致小团体包办。

## 6. 上下文包：默认最小，可自主扩展

默认只给：任务卡全文、本会话角色卡、scope 内文件当前版本、直接依赖的产出摘要、协议速览。

**不给**：全局计划、其他任务列表、全仓库结构。

注意语义：这是“默认不给”而非“禁止去看”。Agent 用原生工具自主探索代码是正常工作行为，
不构成违规。**防全包主力是裁决权，不是信息封锁**——员工能看全公司代码，不等于他会去干全公司的活。

## 7. 审计：detect-only

Sentinel 扫四类问题：任务分支越界写入、主分支漂移（D-Session 直推）、协议违规、会话失联。
它**只记录与上报**：不阻断、不回滚、不改任何任务状态。

这不是能力不足，是权力设计：如果审计者也能惩罚，平台就有了第二个不可复核的权力来源。
真正的权威只有一处——合并终审，而它只做一件事：这个 diff 是否越界。

## 8. 已知边界（诚实清单）

| 边界 | 现状 | 为什么可以接受 |
|---|---|---|
| 事中无法阻止写主仓库 | Sentinel 检测 + 通知，不回滚 | 写了也不算数：合并终审保证账本不被污染 |
| 文件协议要求能写 `.mesh/` | MCP 通道不受此限 | hub 服务器跑在沙箱外；自带沙箱的 CLI 走 MCP |
| 长驻角色仍是 LLM | 调度器自动派发 + 人类随时介入 | 职责在代码里封死，LLM 只做判断不做裁决 |
| capabilities 人工配置 | 未做自动探测 | 计划书明确把它列为 M5 之后研究项 |
| 审查者可能很慢/挂起 | 审查尝试上限 3 次后 blocked 升级 | 宁可停下等仲裁，也不假装通过了 |
| Agent 自己的全局配置仍会生效 | 平台只**追加**角色卡，不改别人的 persona / 规则 / 凭证 | 这是 C3 的同一逻辑：不修改 Agent 的全局身份。防串扰条款把会话身份钉死；实测中 DSH 仍带着它的全局 persona，但任务照做 |
